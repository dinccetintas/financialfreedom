# Phase 1 — UI Design Contract

> Visual and interaction contract for Sign In, Portfolio Create/List, Add-Transaction, and
> Transaction List. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope note:** This is the *first* UI-SPEC in the project. Phase 4 (Presentation Modes,
> Localization & Design System — DES-01/02/03) is the authoritative, project-wide design-system
> phase that will formalize colour/type/spacing/chart styling across every shipped screen and
> add Turkish translation + Simple/Pro mode. This document is not speculative in the meantime —
> it is a real, binding contract for the five Phase 1 screens — but treat every token here as
> the working default Phase 4 will audit and, if needed, consciously supersede, not re-derive
> from scratch.

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn |
| Preset | `style: new-york`, `baseColor: neutral`, `cssVariables: true` |
| Component library | Radix primitives (via shadcn) |
| Icon library | lucide-react |
| Font | Inter (variable), fallback `system-ui, -apple-system, sans-serif` |

**Assumption (auto_mode, recorded explicitly):** `components.json` does not exist because this
repo is genuinely greenfield — per `01-CONTEXT.md` §Existing Code Insights, there is no
`package.json`, no `src/`, not even a scaffolded Next.js app yet (RESEARCH.md's own
installation sequence starts with `npx create-next-app`). The interactive shadcn gate (visit
ui.shadcn.com/create, paste a preset, run `npx shadcn init --preset {paste}`) cannot run today
because there is no Next.js project to initialize into. Rather than block this document on that
chicken-and-egg problem, this contract fixes the preset now (`new-york` / `neutral` /
CSS variables) so the executor runs `npx shadcn init` with a known, non-improvised preset as
literally the first UI-touching task of Wave 0. `new-york` (tighter spacing, bordered inputs)
and `neutral` base were chosen over `default`/`slate` because the "Wall Street portfolio
manager who happens to know your family" framing (`PROJECT.md`) calls for a restrained,
information-dense, low-chroma surface — not a colorful consumer app. Reversible: this is a
config choice, not a schema decision — swapping base color later restyles, it does not migrate
data.

**Font rationale:** Inter has full Latin Extended-A coverage (Turkish dotless ı, ğ, ş, ç, ö, ü)
even though Turkish copy itself ships in Phase 4 — per `01-CONTEXT.md`'s explicit instruction
that "any layout decision that breaks under longer Turkish strings must be decided now." Inter
also ships tabular-figure OpenType features (`font-feature-settings: "tnum"`), which is used
below for numeric columns instead of introducing a second monospace font.

**Components expected from shadcn official registry this phase:** `button`, `input`, `label`,
`form`, `card`, `table`, `dialog`, `alert-dialog`, `dropdown-menu`, `select`, `sonner` (toast),
`badge`, `separator`, `skeleton`, `tooltip`. No third-party registries are declared — see
Registry Safety.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, inline badge padding |
| sm | 8px | Compact stacks (form field to helper text), table cell vertical padding |
| md | 16px | Default element spacing, form field vertical rhythm, card padding |
| lg | 24px | Section padding, dialog padding |
| xl | 32px | Layout gaps between major page regions |
| 2xl | 48px | Major section breaks (e.g. above page title) |
| 3xl | 64px | Page-level top/bottom spacing on desktop only |

**Exceptions:**
- Icon-only buttons (transaction row actions — correct/remove, nav toggle, share-revoke icon)
  render their icon at 20px but reserve a **44×44px minimum touch target** via padding on
  mobile (`<640px`), per the mobile/desktop-equal-priority constraint in `PROJECT.md`. Desktop
  keeps the same target size for pointer-precision consistency rather than shrinking it.
- The transaction list on mobile (`<640px`) collapses from a table to a stacked card layout;
  card internal spacing uses `md` (16px) between the two info lines (date+instrument /
  qty+price+fees) rather than table cell padding — see Layout & Responsive Contract below.

**Layout & Responsive Contract (single breakpoint at 640px, Tailwind `sm:`):**
- `<640px`: Transaction list renders as a vertical stack of cards, one per transaction. Each
  card: line 1 = date (Label, muted) + instrument symbol (Body, semibold); line 2 = quantity ×
  price, with fees shown as a smaller muted line beneath if non-zero. Filter/sort controls
  collapse into a single "Filter & sort" sheet/drawer trigger rather than an inline toolbar.
- `≥640px`: Transaction list renders as a table with right-aligned numeric columns (quantity,
  price, fees, total) using tabular figures; filter/sort controls are an inline toolbar above
  the table.
- Forms (sign-in, add-transaction, create-portfolio) are single-column at every width — never
  a two-column form layout, even on desktop. This avoids a Phase 4 retrofit when Turkish labels
  run longer and a two-column grid would force awkward wrapping.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 (regular) | 1.5 |
| Label | 14px | 400 (regular) | 1.4 |
| Heading | 20px | 600 (semibold) | 1.2 |
| Display | 28px | 600 (semibold) | 1.2 |

- **Body (16px/400/1.5):** form input text, table/card cell content, paragraph copy, dialog body
  text.
- **Label (14px/400/1.4):** form field labels, table column headers, helper/meta text
  (timestamps, "voided" tags), nav item text.
- **Heading (20px/600/1.2):** section titles within a page ("Transactions", "Portfolios"),
  dialog titles, card titles.
- **Display (28px/600/1.2):** page-level titles, empty-state headings.

Only two weights exist in this contract: 400 and 600. Do not introduce 500 or 700 for emphasis
— use color (muted vs. primary text) or size instead.

**Numeric formatting (Phase 1 is USD-only per `01-CONTEXT.md` scope — Turkish/locale-aware
formatting per DES-03 is Phase 4 scope):**
- Currency values (price, fees, total): `$` prefix, thousands comma grouping, exactly 2 decimal
  places — e.g. `$1,234.56`.
- Share quantity: up to 4 decimal places, trailing zeros trimmed — e.g. `10` not `10.0000`,
  but `12.5` stays `12.5`.
- All numeric table/card columns use `font-feature-settings: "tnum"` (tabular figures) and are
  right-aligned in the desktop table view.
- Dates: `MMM D, YYYY` (e.g. `Aug 16, 2026`) in Phase 1's English-only UI — this format is
  swapped for locale-aware formatting in Phase 4, not before.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` | Page background, form/card surfaces |
| Secondary (30%) | `#F3F4F6` | Table zebra rows, nav/sidebar background, muted card backgrounds |
| Accent (10%) | `#1D4ED8` | Primary CTA buttons, focused input border, active nav indicator, links |
| Destructive | `#DC2626` | Destructive action buttons, destructive-confirmation dialog accents, form error text/border |
| Text primary | `#111827` | Default body/heading text |
| Text muted | `#6B7280` | Labels, timestamps, helper text, placeholder text |
| Border | `#E5E7EB` | Input borders, table row dividers, card borders |

**Accent (`#1D4ED8`, blue-700) is reserved for exactly:**
1. Primary CTA buttons ("Sign in", "Create portfolio", "Add transaction", "Send reset link")
2. Focused/active form field border and focus ring
3. The active item indicator in primary navigation
4. Text links (e.g. "Reset password" link on the sign-in screen)
5. Selected/checked state on radio buttons, checkboxes, and select triggers

Accent is **not** used for: table row highlighting, badges/tags, data values themselves, or any
decorative purpose. There is no gain/loss green/red convention in this contract — Phase 1 shows
no P&L or valuation figures (that begins in Phase 3/5); when it does, that convention is a
Phase 3/4 design decision, not one this document should pre-empt.

**Destructive (`#DC2626`, red-600) is reserved for exactly:**
1. "Remove transaction" and "Remove access" (revoke share) buttons and their confirmation
   dialogs
2. Inline form validation error text and the red border on an invalid field
3. Toast/banner copy reporting a failed destructive action

No dark mode is specified in this contract — no v1 requirement calls for it (`UI-01` through
`UI-08` cover locale/mode/prescriptiveness/attention-first-home, not light/dark theming). shadcn
ships dark-mode CSS variables by default; leave them un-customized rather than either building
or explicitly disabling dark mode in Phase 1.

## Visual Hierarchy

One focal point per screen — the single element that should draw the eye first. Declared here so
that screens executed independently do not each invent their own priority. Where the focal point is
a CTA it takes the accent color per the Color contract; where it is data it takes the heaviest type
step present on that screen (semibold, one size up from Body) rather than accent color.

| Screen | Focal point | How it is expressed |
|--------|-------------|---------------------|
| Sign in | The "Sign in" primary CTA | Accent-filled, full-width button; the only accent element on the screen |
| Request password reset | The "Send reset link" primary CTA | Accent-filled, full-width; email field sits above it in Body weight 400 |
| Set new password | The "Set new password" primary CTA | Accent-filled, full-width; password rules render as Label (14/400, muted) and never compete |
| Portfolio list | The portfolio name on each card | Heading (20/600); value/metadata rows stay Body 400 muted. The "Create portfolio" CTA is accent but sits above the fold as a single button, not repeated per card |
| Portfolio create | The name input field | Focused-field accent border on mount (autofocus); the CTA is the second-strongest element |
| Add transaction | The instrument field, then quantity × price as a pair | Instrument autofocuses and carries the accent focus border; quantity and price render in tabular figures at Body 600 while the remaining fields (date, fees, currency) stay Body 400 |
| Transaction list | The instrument symbol + date row | Instrument symbol Body 600, date Label muted directly beside it — on both the ≥640px table row and the <640px card. Numeric columns are right-aligned tabular figures but are NOT the anchor; no accent color appears on any row |

**Rule that holds across all seven:** exactly one focal point per screen. If a screen appears to
need two, the second is demoted to Body 600 without accent. Superseded/corrected transaction rows
(D-17) are rendered muted and are never the focal point, even though they remain visible in history.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA — Sign in | "Sign in" |
| Primary CTA — Request reset | "Send reset link" |
| Primary CTA — Set new password | "Set new password" |
| Primary CTA — Create portfolio | "Create portfolio" |
| Primary CTA — Add transaction | "Add transaction" |
| Primary CTA — Share portfolio | "Share portfolio" |
| Empty state — Portfolio list (heading) | "No portfolios yet" |
| Empty state — Portfolio list (body) | "Create a portfolio to start tracking what you own." |
| Empty state — Transaction list (heading) | "No transactions yet" |
| Empty state — Transaction list (body) | "Record your first buy to see it here." |
| Error — Sign-in failure | "That email or password isn't right. Try again, or reset your password." (never indicate which of the two was wrong) |
| Error — Add-transaction validation (pattern) | "{Field} needs a value" / specific: "Quantity must be greater than zero.", "Price can't be negative.", "Pick a date for this transaction." |
| Error — Transaction list load failure | "Couldn't load your transactions. [Retry]" |
| Error — Instrument search unavailable | "Couldn't search instruments right now — you can still add one manually." |
| Destructive — Remove transaction | "Remove this transaction? It stays in your history — nothing is deleted." / confirm button: "Remove" |
| Destructive — Remove access (revoke share) | "Remove {name}'s access to this portfolio? They won't be able to view it anymore." / confirm button: "Remove access" |

**Tone:** plain, direct, no finance jargon in Phase 1 copy — the father is one of four users and
`PROJECT.md` is explicit that he "needs everything to be immediately understandable." Avoid
words like "instrument," "ledger," "lot," or "void" in user-facing copy even though those are
the correct internal/schema terms — say "stock," "transaction," and "remove."

**i18n forward-compatibility (Phase 4 implements Turkish; this phase must not break under it):**
Every string above is treated as a translatable key, not a hardcoded literal, even though only
the English value ships in Phase 1. No button, label, or nav item uses a fixed pixel width that
would clip a ~30–40% longer Turkish equivalent (e.g. "Portföy oluştur" vs. "Create portfolio")
— buttons and labels size to content with a min-width, not a fixed width.

## UI Considerations

> Populated by the ui-phase UI-consideration probe. Shape-rooted UI *state* coverage
> (empty / loading / error / populated / partial / overflow / zero-one-many / long-text) across
> the five Phase 1 surfaces: sign-in/reset forms, portfolio create/list, add-transaction form,
> transaction list, share/revoke control.

Applicable state considerations resolved: 19 covered, 3 backstop, 2 unresolved

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | Portfolio list (list-collection) | ✅ covered | First-time user with zero portfolios sees the documented empty-state heading/body (see Copywriting Contract) with the "Create portfolio" CTA inline |
| empty | Transaction list (list-collection) | ✅ covered | A portfolio with zero transactions shows the documented empty-state heading/body with the "Add transaction" CTA inline |
| loading | Sign-in form (form) | 🧪 backstop | Submit button shows a spinner and disables while the auth request is in flight; no explicit test scoped yet — verify at execution |
| loading | Portfolio list, Transaction list (list-collection) | 🧪 backstop | Skeleton rows render while the server-scoped query resolves; no explicit test scoped yet — verify at execution |
| loading | Instrument search (interactive-control) | ✅ covered | Debounced search shows an inline spinner inside the input while the Finnhub lookup is in flight (INST-03) |
| loading | Filter/sort controls (interactive-control) | ✅ covered | Filtering/sorting runs client-side over an already-fetched page (per RESEARCH.md architecture) — no loading state needed, re-render is instant |
| error | Sign-in form (form) | ✅ covered | Invalid credentials show the documented inline error banner; never reveals which field (email vs. password) was wrong |
| error | Add-transaction form (form) | ✅ covered | Field-level Zod validation errors render inline per-field, following the documented copy pattern |
| error | Instrument search (interactive-control) | ✅ covered | Provider unreachable falls back to manual instrument entry (D-15) with the documented fallback copy — search failure never blocks recording a transaction |
| error | Transaction list load (list-collection) | 🧪 backstop | Query failure shows the documented retry copy and a retry affordance; no explicit test scoped yet — verify at execution |
| error | Share/revoke control (interactive-control) | ✅ covered | A failed revoke shows an inline toast error; the shared-with list stays unchanged until the action actually succeeds |
| populated | Transaction list (list-collection) | ✅ covered | Netted view by default (corrected values shown, superseded rows hidden per D-17), right-aligned tabular numeric columns on desktop, card layout on mobile, sortable by date/instrument, filterable |
| populated | Portfolio list (list-collection) | ✅ covered | Card/row per portfolio showing name, base currency, and transaction count |
| partial | Add-transaction form (form) | ✅ covered | Fees is optional and defaults to 0; date/instrument/quantity/price/currency are required and block submit via Zod until present |
| partial | Instrument search results (interactive-control) | ⚠ unresolved | Behavior when Finnhub returns a company match with no resolvable `exchange_mic` is not specified — planner assumption: treat as no-match and fall through to the manual-entry path (D-15) |
| overflow | Transaction list (list-collection) | ✅ covered | Instrument name truncates with ellipsis + tooltip on desktop, wraps on mobile card layout; list paginates at 50 rows per page rather than rendering unbounded rows |
| overflow | Portfolio name (static-content) | ✅ covered | Long portfolio names truncate with ellipsis in list/nav views; full text is always visible in the portfolio's own settings/detail view |
| overflow | Primary nav portfolio switcher (nav) | ⚠ unresolved | No defined maximum for how many portfolios (own + shared) render in the switcher dropdown before it needs internal scrolling — planner assumption: make the dropdown internally scrollable past ~8 items, revisit if Phase 2 bulk-onboarding makes this common sooner |
| zero-one-many | Transaction list (list-collection) | ✅ covered | Zero → empty state (above); one → single card/row, no special-case copy needed; many → table/card list with a sticky header on mobile scroll |
| zero-one-many | Portfolio list (list-collection) | ✅ covered | Zero → empty state; one/many → list/grid with an accurate "N portfolios" count label |
| long-text | Add-transaction form labels + instrument name (form) | ✅ covered | Labels and buttons size to content with a min-width rather than a fixed width, so longer Turkish equivalents don't clip when Phase 4 translates them |
| long-text | Error messages (static-content) | ✅ covered | Error banners/toasts wrap to multiple lines rather than truncating — the full message is always readable |
| long-text | Nav portfolio switcher label (nav) | ✅ covered | Truncates with ellipsis at a fixed max-width; full name available via tooltip on hover (desktop) or on tap-through (mobile) |
| long-text | Shared-with family member name (interactive-control) | ✅ covered | Full names truncate in the share/revoke select control; fully visible once selected or on hover |
